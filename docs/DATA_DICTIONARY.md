# V-IMS AI Prototype — Data Dictionary

This document specifies the database tables, fields, data types, foreign key constraints, and synthetic vs. public master data distinctions in `data/generated/vims_ai_demo.db`.

---

## 2. Table Specifications

### 2.1 `public_products` (Public Master Data)
- `public_product_id` (TEXT, PK): Public reference ID (e.g. `PROD001`).
- `brand_name` (TEXT): Brand reference (e.g., *Vinamilk 100% Fresh Milk*).
- `product_type` (TEXT): Category (e.g., *Fresh Milk*, *Yogurt*, *Condensed Milk*).
- `official_reference_url` (TEXT): Public URL reference.

### 2.2 `skus` (Public Master Data)
- `sku_id` (TEXT, PK): SKU identifier (e.g., `SKU001` to `SKU030`).
- `sku_name` (TEXT): Product description.
- `public_product_id` (TEXT, FK -> `public_products.public_product_id`).
- `category` (TEXT): Product category.
- `pack_size` (TEXT): Packaging unit (e.g., *1L*, *180ml*, *380g*).
- `shelf_life_days` (INTEGER): Total shelf life duration in days.

### 2.3 `locations` (Master Data)
- `location_id` (TEXT, PK): Location code (`LOC01`, `LOC02`, `LOC03`).
- `location_name` (TEXT): Facility name (e.g. *Central Warehouse*, *Branch Depot North*).
- `location_type` (TEXT): Facility classification.

### 2.4 `users` (Synthetic Demo Data)
- `username` (TEXT, PK): Login handle (`warehouse.manager`, `planner`, `warehouse.staff`, etc.).
- `password_hash` (TEXT): SHA-256 password hash (`Demo@123`). *Never returned by API endpoints.*
- `full_name` (TEXT): User's full display name.
- `role` (TEXT): User authorization role.
- `email` (TEXT): Contact email.

### 2.5 `lots` & `inventory_balances` (Synthetic Operational Data)
- `lot_id` (TEXT, PK): Lot instance identifier (`LOT0001` to `LOT0120`).
- `sku_id` (TEXT, FK -> `skus.sku_id`).
- `location_id` (TEXT, FK -> `locations.location_id`).
- `manufacturing_date` (TEXT): ISO date string (`YYYY-MM-DD`).
- `expiry_date` (TEXT): ISO date string (`YYYY-MM-DD`).
- `on_hand_qty` (INTEGER): Total physical inventory balance.
- `available_qty` (INTEGER): Inventory available for sale or allocation.
- `reserved_qty` (INTEGER): Inventory allocated to existing orders.
- `quarantine_qty` (INTEGER): Inventory held for inspection.

### 2.6 `recommendations` & `audit_logs` (Prototype Workflow Data)
- `recommendation_id` (TEXT, PK): Proposal code (`REC0001` to `REC0040`).
- `recommendation_type` (TEXT): Type (`REPLENISHMENT`, `TRANSFER`, `EXPIRY_ACTION`).
- `sku_id` (TEXT, FK -> `skus.sku_id`).
- `lot_id` (TEXT, FK -> `lots.lot_id`, nullable).
- `source_location_id` (TEXT, FK -> `locations.location_id`, nullable).
- `target_location_id` (TEXT, FK -> `locations.location_id`, nullable).
- `proposed_qty` (INTEGER, Immutable): AI recommended quantity.
- `adjusted_qty` (INTEGER, Nullable): Human manager modified quantity.
- `reason` (TEXT): Explanation text generated for proposal.
- `status` (TEXT): Decision state (`PENDING`, `APPROVED`, `REJECTED`).
- `audit_id` (TEXT, PK): Sequential audit code (`AUD0001` ...).
- `actor_username` (TEXT): Authenticated user who performed the mutation.
- `action` (TEXT): Mutation action (`MODIFIED`, `APPROVED`, `REJECTED`).
- `action_timestamp` (TEXT): ISO timestamp generated by backend.
